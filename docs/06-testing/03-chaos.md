# Chaos

> 提案；当前未实现。

> 故障模型的每一行都有一个注入。没有注入测试的故障模式是假设。

## 1. 问题

故障行为是设计中最常被描述、最少被执行的部分。描述是免费的，写错也不花钱。

## 2. 目标

- 为 [05-operations/02-failure-model.md](../05-operations/02-failure-model.md) 的每一行
  提供一个注入。
- 断言时限，而不只是“最终恢复了”。
- 运行那些单实例测试在结构上无法覆盖的用例。

## 3. 非目标

- 注入应用故障。
- 硬件故障仿真。

## 4. 注入矩阵

| 注入 | 期望 | 断言的时限 |
|---|---|---|
| 杀掉一个 worker | lease 过期；从 lookup 移除 | `ttl + sweep` |
| 用 `SIGSTOP` 暂停一个 worker | 与死亡相同；Readiness 先降级 | readiness 周期 |
| 阻塞一个 worker 的主线程 | `/introspect` 仍应答 | 立即 |
| 杀掉一个被监督的子进程 | 上报；孙进程也一并消失 | 约 1 s |
| 杀掉一个 Node Agent | 其进程被回收 | node ttl |
| 杀掉一个 Registry 副本 | 失败转移；不中断 | 一次请求 |
| 杀掉**全部** Registry 副本 | lookup 走缓存；peer 仍可达 | 无上界，被上报 |
| 空重启一个 Registry 副本 | worker 重新注册 | 一个 heartbeat 间隔 |
| 杀掉一个 Cell 控制器 | standby 以新 generation 接管 | cell ttl |
| 把一个 Cell 与 global 分区 | Cell 完成有效工作，不申请新的 | cell ttl |
| 杀掉 global leader | 选举；Cell 继续 | `leader_ttl` |
| **旧 leader 在存活状态下返回** | 被 fence 出去 | 立即 |
| **旧 worker 存活时重启该 worker** | 旧的被取代并 fence | 一个 heartbeat |
| 填满 Admission 队列 | 显式拒绝而非停滞 | 立即 |
| worker 上的时钟跳变 | fencing 不受影响 | 立即 |

加粗的三行是只有做对了才会失败的用例。

## 5. 必须做对的那几个用例

### 5.1 脑裂要求两个进程都活着

先杀掉旧进程的重启测试，证明不了任何关于 fencing 的事。旧进程必须在新进程注册时**仍在
运行、仍在 heartbeat、仍在尝试写入**。断言是：Registry 提供新 endpoint；旧进程得知自己被
取代；旧进程发出的写入被第三方拒绝。

### 5.2 可用性要求至少两个副本，并杀掉一个

此前的实现通过了全部单副本测试，而两个副本因共享 identity 而永久损坏 —— 调用提交给其中
一个、结果却去另一个取。用一个实例做的高可用测试，是贴错标签的正确性测试。

### 5.3 全量丢失必须被执行，不能靠推理

“读会回落到缓存”是一句关于“只有在一切都宕机时才会运行的代码”的论断。它必须被真的执行：
杀掉每个副本，然后断言 lookup 能返回、被上报为陈旧、且 peer 调用仍然成功。

## 6. 方法

注入由框架施加于真实进程，并记录时间线，使指标变化可以归因到某个步骤。每个用例断言：

1. 故障被检测到。
2. 在声明的时限内。
3. 由声明的检测方检测。
4. 爆炸半径与声明一致，且不更大。

第四点通常被省略，而它正是区分“被限制住的故障”与“碰巧没扩散的故障”的那一条。

## 7. 不稳定性

Chaos 测试对时序敏感，偶尔会假失败。策略是：隔离，绝不删除。被隔离的 chaos 测试是一个
已知缺口；被删除的是一个未知缺口。

时间常量可由环境变量覆盖，因此用例以秒级而非生产 TTL 运行。

## 8. 正确性不变量

- 故障模型的每一行至少有一个注入。
- 每个注入断言一个时限，而不只是最终恢复。
- 可用性注入使用两个及以上实例并杀掉一个。
- 脑裂注入保持被取代的进程存活。
- 没有任何注入以“没有抛异常”作为通过条件。
